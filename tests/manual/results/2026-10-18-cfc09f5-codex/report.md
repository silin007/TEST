## 3. 已确认阻塞问题

### P0-001｜B0：未知更高版本存档被自动覆盖（SAVE-07）

- 前置：隔离目录主档为 schema_version=999 的完整夹具，保留原始文本；无需用户选择新建或恢复。
- 操作：实例化实际主场景，正常运行约 3 秒，越过启动后的 1 秒防抖保存。
- 实测：`disk_schema=1`、`autosave_stopped=false`，主档字节已变化。程序拒绝加载以后，仍将默认宠物作为 v1 自动提交。
- 预期：未知版本只读拒绝，禁止自动写回，原档和备份保持可恢复。
- 影响：可能丢失较新版本用户数据。是进入 P1 的首要阻塞。
- 根因位置：`SaveService.load_snapshot()` 的 UNSUPPORTED_VERSION 分支没有建立写保护；`AppController.start_app()` 仍调度保存，`_commit_save()` 未因 `_load_problem` 拒绝写入。
- 修复方向：对未知/待选择恢复状态锁定普通保存，只有完成隔离并由用户明确选择的恢复/新建事务才能解除；补测启动、防抖、周期保存及退出，不仅测一次 load 返回值。
- 证据：acceptance-integration.stdout.txt；对应新增集成测试。

### P0-002｜B1：普通帧率下模拟时间丢失（SIM-02；影响 PET-03、SIM-05、STAB-01）

- 操作：分别按 15/30/60 FPS 输入精确 60 秒的固定 idle 时间序列。
- 实测：三组均为 `ticks=0`、`elapsed=0`、`energy=80`；正确基线约为 600 tick / 60 秒 / energy=79.4。
- 导出构建复证：一个 FLOATING 运行样本墙钟约 230.70 秒、渲染 13,832 帧，却只有 1 tick / 0.1 秒累计模拟。偶发长帧产生一个 tick，不能算连续推进。
- 根因：`PetSimulation.advance_time()` 中 `var accumulator := dt` 是局部变量，每次调用丢弃不足 0.1 秒的余数；AppController 也没有提供累计器。
- 修复方向：保持跨帧累计余数，补步使用固定 dt；正常短暂停顿保留时间，大于 5 秒的断点按设计清积压；断言必须同时检查 tick、累计模拟秒数和需求值。
- 证据：acceptance-audit.stdout.txt、[runtime-observer.jsonl](runtime-observer.jsonl)。

### P0-003｜B1：动作实例 ID 重复，旧事件能中断新动作并发奖（PET-04）

- 操作：同一个 tick 内请求 happy，取消，再启动 walk；将已取消 happy 的完成事件延迟送达。
- 实测：旧 ID=1，新 ID=1；`walk → idle`，comfort `50 → 52`。
- 预期：每个实例单调递增，已取消实例晚到的事件无副作用，不结束当前 walk，也不奖励。
- 根因：实例 ID 由 tick 算出，同一 tick 多次动作复用；`on_action_event()` 未校验事件是否属于当前有效实例就修改状态和奖励。
- 修复方向：独立单调实例计数器、终态/取消记录与有效事件校验；将“重复成功事件”和“取消后旧事件”分别回归。
- 证据：acceptance-audit.stdout.txt。

### P0-004｜B1：透明悬浮窗实际显示黑色矩形（WIN-01）

- 操作：独立 Windows 导出构建切回 FLOATING，并置于白色记事本编辑区上方观察。
- 实测：可见黑色矩形遮住白色背景。只读探针记录 `transparent=true`、`transparent_bg=true`，但 `transparency_allowed=false`、`transparency_available=false`。
- 预期：角色外背景能看到底层应用，无黑底。
- 定位：原工程缺少有效的 `display/window/per_pixel_transparency/allowed` 配置；设置窗口的 transparent 标志没有使当前 D3D12 构建具备透明能力。其余渲染兼容性须在补齐配置后再测，不能直接推定一定可用。
- 修复方向：先使项目透明许可与窗口/视口配置一致，复测当前渲染路径；若仍不可用，再用明确记录的备选渲染方案验证。
- 证据：[floating-black-background.png](floating-black-background.png)、runtime-observer.jsonl；白底上的遮挡已在本轮桌面操作中观察，不归档含用户其他标签的整屏截图。

### P0-005｜B1：正常快速双击未打开 FULL（WIN-05）

- 操作：在角色命中区域以系统双击输入操作，原导出构建和观察构建均尝试；观察构建保存按钮事件。
- 实测：系统已产生 `double_click=true`，应用仍保持 FLOATING。记录中的一次点击为 148206/148226 ms 按下/释放，第二次 148365 ms 按下，距首次释放 139 ms。
- 根因：WindowController 把每次鼠标按下/释放都作为拖动开始/结束；即使没有移动也触发 150 ms 的点击抑制，第二次点击被过滤。
- 修复方向：区分按下、越过阈值的真实拖动与点击；仅真正拖动结束才抑制点击；重新验证单击、双击、拖动三者互斥。
- 证据：[runtime-inputs.jsonl](runtime-inputs.jsonl)、runtime-observer.jsonl、native-first-run.log。

## 4. 未作通过结论的观察与风险

- **WIN-02 跨应用穿透**：从 FULL 界面真实点击进入 FOCUS 后，探针确认 PASSTHROUGH=true。角色覆盖记事本文本区时，操作工具的目标命中检测两次仍识别为 MOTE，阻止向记事本注入点击。它是工具取证受阻，不能等同于底层应用实际收到或未收到鼠标；本轮不判通过，需人工真实点击或可验证底层事件计数的复测。没有绕过工具命中保护。操作与错误摘要见 [cross-process-hit-test.txt](cross-process-hit-test.txt)。
- **WIN-03 拖动**：短拖动自动操作中未观察到窗口位移，并观察到 happy 请求。工具输入序列较短，尚不足以区分真实拖动处理问题与事件合并，保留为待人工慢速拖动复测；双击缺陷已有独立充分证据。
- **WIN-06/07 恢复**：TRAY 的 ready=true 只是程序状态。托盘菜单、隐藏恢复和入口失效的完整链路未执行，不能标通过。没有使用任务管理器强退代替正常恢复；本轮结束时仅清理了自己启动的测试进程。
- **FULL 界面布局**：在本次缩放下诊断文本与右侧控件有裁切，退出控件未完整显示。需要 UI 布局复测，不能将自动装配通过等同于完整窗口可用。
- **焦点策略**：代码产生 allow_focus=false，但当前窗口控制器没有消费该字段；探针在 FOCUS 仍显示 unfocusable=false。这是待修风险，不以该标志单独断言已经发生抢焦点。
- **环境传递**：PetSimulation 的 `_environment()` 固定 can_walk=true，没有接入 WindowController 的实时环境；即使位移层另有阻止，行为决策限制本身仍待验证。
- **SIM-04 覆盖不足**：现有所谓墙钟回拨测试实际输入的是一个正向 86400 秒 dt，只证明大时间断点不补算，不证明墙钟回拨/前跳注入覆盖。
- **测试隔离**：现有 run_tests.bat 仍使用工程正常 user://，不能在有真实宠物存档的配置下直接跑清理型测试。本轮通过副本规避，后续应让测试入口默认隔离。
