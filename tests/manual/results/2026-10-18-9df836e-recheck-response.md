## 2. 关于 §4「下一步优先执行跨应用穿透」：已实现，但仍需人工取证

复验 §4 将「物理托盘恢复 + 跨应用穿透」列为下一步优先项。其中**跨应用穿透的实现**已完成，**物理托盘点击**我无法自动化。

### 2.1 已实现：接入 Windows Mouse Passthrough（MIT）

架构 §4.3 记录「`Window.mouse_passthrough` 不能据此承诺跨应用穿透」，该扩展正是解决这一点：直接对 HWND 设 `WS_EX_LAYERED | WS_EX_TRANSPARENT`。

改动位置 `scripts/desktop/window_controller.gd`：

- 新增 `MP_SINGLETON` 常量与三档穿透级别 `system` / `app` / `none`
- `set_mouse_mode_internal()` 进入穿透时：先设原生 `Window.mouse_passthrough`（同应用级），再尝试系统级扩展；成功则级别升为 `system`，失败保持 `app`
- 新增 `_set_system_passthrough()`，用 `Object.call()` 动态调用（全静态类型下 GDExtension singleton 方法无法静态推导）
- 新增 `get_passthrough_level()` 与 `has_system_passthrough()`；穿透级别同时进 `get_environment()` 与 `get_diagnostics()`

**关键设计：这是可选增强，不是硬依赖。** 扩展缺失时回退原生方案，功能不缺失，仅穿透范围收窄为同应用；诊断如实标注当前级别，不会虚报 `system`。

### 2.2 实测证据

| 场景 | 实测结果 |
|---|---|
| 扩展存在 + 进入穿透 | `has=true`，`level=system`，诊断与环境同步为 `system` |
| 扩展存在 + 退出穿透 | `level=none`（系统级标志已清除） |
| 扩展缺失（`addons/` 移走 + 重新导入） | `has=false`，`level=app`，正确降级 |
| 代码虚报（故意让守卫返回 true） | 断言 **FAIL**：`available=false → app，实际 system` |

最后一行是**回归断言的有效性验证**——故意注入错误后断言确实报错，确认它能抓住虚报，之后已还原。

新增断言 8 条（`_test_win02_passthrough_level`），为**环境自适应**设计：不假设扩展存在，只校验「能力 → 级别」的对应关系，因此在任何机器上都能验证守卫与降级。全量由 230 增至 **238 条，全绿**。

### 2.3 边界：这不等于 WIN-02 已通过

以上证明的是**能力已具备且状态可观测**。`WS_EX_TRANSPARENT` 是否真的把点击传给了记事本/浏览器，仍需**人工在导出构建上点击验证**——自动化无法替代，这正是 WIN-02 的取证要求。

### 2.4 另一个已知风险（作者自述）

> the engine can update the window style and clear the flags

引擎自身更新窗口样式时可能清除扩展设置的标志。当前实现未做「模式切换后重应用」，需在人工验证时一并观察；若确有清除，再补重应用逻辑。

## 5. 关于「插件复评与设计调整建议」的批评：已采纳并修正

复评文件（`docs/插件复评与设计调整建议_2026-10-18.md`）指出我这一版实现存在**虚报**，批评成立，已逐条修正。

### 5.1 最严重的一条：我的 `system` 是虚报

> 上游 `set_passthrough` 返回 void，HWND 为空时直接返回，Windows API 结果未检查。本地 `_set_system_passthrough()` 在调用后无条件返回 true，继而显示 system。这个值最多证明"调用已发出"，不能证明样式或跨应用点击生效。

确实如此。我的断言在防"虚报"，但**实现本身就在虚报**——把"请求已发出"标成了 `system`（读起来像已验证）。已修正：

| 项 | 修正前 | 修正后 |
|---|---|---|
| 级别命名 | `system`（暗示已验证） | `system_requested`（明确"已请求"） |
| 注释 | "系统级扩展生效" | 明示上游返回 void、无样式位回读、不存在 verified 级别 |
| 断言 | 校验能力→级别一致 | 新增护栏：级别不得包含 `verified` |

现在三档为 `system_requested` / `app` / `none`，三者**均非"已验证"**。跨应用生效只能人工点击取证，代码不得宣称。

### 5.2 属性顺序：穿透改为最后应用

复评指出：窗口属性变化可能清除扩展样式，先设穿透会静默失效。已把 `set_mouse_mode_internal()` 从"焦点策略之前"移到 `_apply_focus_policy()` 与 `validate_geometry()` **之后**。

### 5.3 探针假通过：已修

`probe_mousepassthrough.gd` 在 singleton 不存在时仍 `quit(0)`。已改为 `quit(1)`，实测确认：扩展缺失（移走 `addons/` + 重新导入）时 Godot 退出码为 **1**。

### 5.4 其余两条的处置

- **"恢复也应验证"**：关闭穿透同样无回读，与开启同源。当前实现如实不宣称；若要真正验证，需上游提供样式回读（复评建议的最小维护分支），属后续工作。
- **"回退不能冒充达标"**：同意。扩展缺失时降级为 `app`，诊断如实标注；README 与本文档均写明这不等于 WIN-02 通过。

### 5.5 我对复评中两条更正的接受

1. **Maaack**：我不该由"GlobalState 不适用"推导"整个模板不可用"。设置系统与 GlobalState 不是同一入口；仅复用设置界面不会自动回退 P0-001。已在草案中收窄表述。
2. **State Charts**：它是"选中后经过哪些步骤"的执行层，与 UtilityAI 的"选什么"是分层而非替代关系。已改为"P0 保留现状、P1 执行层候选"。
