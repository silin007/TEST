## 3.1 验收报告 5 个阻塞缺陷的修复（报告 §6 顺序）

| 缺陷 | 根因 | 修复 | 回归断言 |
|---|---|---|---|
| **P0-001** 未知版本存档被覆盖 | `load_snapshot()` 返回 `UNSUPPORTED_VERSION` 后自动保存照常运行，一次 60s 周期保存即把高版本档覆盖为 v1 | `SaveService` 增加写入锁：`lock_writes(reason)` / `is_write_locked()`；`save_snapshot()` 与 `_commit()` **双道拦截**；所有失败分支（主档缺失有候选、主档损坏有/无备份、UNSUPPORTED_VERSION、schema 非法、结构非法有/无候选）全部加锁；仅 `load_snapshot()` OK、`restore_from_candidate()` 成功、`start_new_save()` 成功三处解锁 | `P0-001 连续 5 次自动保存全部被拒绝`、`原档字节未被改动`、`未生成降级备份`、`主档缺失但有候选 → RECOVERABLE（非 MISSING）` 等 13 条 |
| **P0-002** 普通帧率下模拟时间丢失 | `advance_time()` 里 `var accumulator := dt` 是**局部变量**，每帧余数被丢弃；60FPS（dt≈0.0167）永远凑不满 0.1s tick，模拟实际停摆 | 改为跨帧字段 `_accumulator`，`while` 循环消化；保留 `MAX_CATCH_UP_TICKS` 上限并在超限时 `fmod`；断点（>5s）时清零；新增 `get_accumulator()` | `60/75/144FPS × 60s` 三帧率下同时断言 **tick≈600、elapsed≈60s、needs 确实推进、余数 < SIM_DT**（报告要求三项同验） |
| **P0-003** 实例 ID 重复、旧事件发奖 | 实例计数器在取消后重排，旧动作的迟到事件命中新实例 id，把奖励错发 | `_instance_seq` 单调递增 + `_closed_instances` 关闭表（上限 256）+ `_active_instance_id` 三件套；`on_action_event()` 依次拒绝 `id<=0`、已关闭实例、非活动实例 | `实例 ID 单调递增不重复`、`旧实例事件不发奖且不结束当前动作`、`当前实例事件正常发奖`、`重放已关闭实例不发奖` |
| **P0-004** 导出后显示黑色矩形 | `project.godot` 缺两个开关，探针证实均为 `false` | `[display] window/per_pixel_transparency/allowed=true`、`[rendering] viewport/transparent_background=true` | 需导出构建实机确认（headless 无窗口表面） |
| **P0-005** 正常快速双击未打开 FULL | `WindowController` 把**每次按下/释放**都当作拖动开始/结束，即使位移为 0；于是释放总是触发 150ms 点击抑制，第二下被吃掉 | 输入处理拆为 `_begin_press` / `_update_drag` / `_end_press` 三段，以 `DRAG_THRESHOLD=4px` 区分点击与拖动，新增 `did_drag_occur()`；`drag_ended` 只在真实拖动后发出；AppController 改用系统 `InputEventMouseButton.double_click` 判定双击，不再自算 300ms 窗口 | WIN-05 共 16 条：零位移不算拖动、2px 抖动仍在阈值内、越阈值触发 started/ended 各一次、下次按下复位标记、模式切换不遗留按下状态 |

## 3.2 同期完成的两项加固

1. **显式新建事务原子化**：`quarantine_all_for_reset()` 在隔离成功后解锁（否则新建后的首次提交被自己的锁拦住），
   隔离失败则**保持锁定**；新增 `start_new_save(snapshot)` 作为唯一入口（隔离 → 丢弃身份 → 首次提交），
   `AppController._create_new_save()` 改用它，不再有「只解锁没隔离」的半状态。
2. **FULL 界面裁切**：诊断文本改为 `ScrollContainer` + `autowrap_mode`，按钮行与恢复区用
   `SIZE_SHRINK_END` 固定在底部，长诊断不再把控件顶出 960×640 窗口。
3. **`allow_focus` 已消费**：`WindowController._apply_focus_policy()` 用 `Window.unfocusable`
   （4.7.2 探针确认存在）实现——FLOATING/FOCUS/HIDDEN 不夺焦点，FULL 接受焦点。


## 4. 实施期实测到的引擎事实（影响文档判断）

1. **`Window.mouse_passthrough` 在 4.7.2 是 bool**（整窗穿透）；局部多边形另在 `mouse_passthrough_polygon`。
   → 官方描述仍不保证跨应用命中，WIN-02 必须在导出构建上实测。
2. **`StatusIndicator` 没有 `is_system_tray_available()`**；`set_menu()` 接受 `NodePath`。
   → 托盘自检只能间接进行；已实现「托盘失败即建立独立常驻小窗口」的等效入口，O-04 仍需实机确认。
3. **无 `Animation.TYPE_ROTATION`**（改名 `TYPE_ROTATION_3D`，仅 Node3D）；2D 骨骼用 `TYPE_VALUE` + `":rotation"`。
   动画须加入 `AnimationLibrary`（`AnimationPlayer.add_animation()` 已移除）。
4. **`Bone2D.rest` 默认全零（det=0）**，不显式设置会在骨架求逆时报 `Condition "det == 0"`；已在 pet.tscn 逐骨骼设置 rest。
5. 叶子骨骼（Head/ArmLeft/ArmRight）会产生 Godot 自身的 “No Bone2D children” 告警，属预期行为。
