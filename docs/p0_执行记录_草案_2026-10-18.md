## 3.3 P0-006：隐藏主窗口被引擎拒绝（08df5df 复验报告 §4）

**现象**：点击"隐藏宠物"后应用 `mode=HIDDEN`，但真实 `Window.visible=true`、窗口仍在桌面；
stderr 报 `Can't change visibility of main window.`（scene/main/window.cpp:1017）。
旧 `_apply_native_attributes()` 对主窗口执行 `win.visible=false` 后**无条件 return OK**，
上层因此提交了 HIDDEN 状态——应用状态与平台状态分裂。

**探针实测**（`tests/probe/probe_hide.gd`，真实 Windows 驱动）：

| 手段 | 结果 |
|---|---|
| `win.visible = false` | ❌ 引擎拒绝，visible 仍为 true |
| `DisplayServer.window_set_mode(MINIMIZED)` | ✅ `window_get_mode()` 回读 = 1，恢复 WINDOWED 正常回 0 |
| `WINDOW_HANDLE` 原生句柄 | 存在（HWND 非 0），可留作 P1 的托盘级隐藏备选 |
| `win.size = 1×1` | 被钳制为 180×64，且属伪隐藏，禁用 |

**修复**（`window_controller.gd`）：

1. `_hide_native()`：改用 `window_set_mode(MINIMIZED)` 并**回读校验**——只有引擎确认
   进入 MINIMIZED 才返回 OK，否则 `ERR_UNAVAILABLE`。
2. `_can_hide_natively()`：headless/dummy 显示驱动下直接判不支持，避免假成功。
3. `apply_mode()` **失败整体回滚**：快照原 mode/mouse/can_walk/allow_focus，
   平台拒绝时全部还原并重应用原窗口外观，绝不留下分裂状态。
4. `restore_visible()` 不再写 `win.visible=true`（主窗口该属性恒为 true 且不可改），
   改为 `_restore_from_minimize()`；只还原由本控制器造成的最小化，不干扰用户手动最小化。
5. `validate_geometry()` 在最小化时跳过：最小化窗口的 position 不代表可见位置，
   强制修正会污染"隐藏前矩形"。
6. 新增 `get_platform_state()`（window_mode/minimized/hidden_by_minimize/can_hide/display_driver），
   诊断**同时**给出应用内部 mode 与平台真实状态（`AppController.get_diagnostics()` 已合并）。
7. `AppController` 记录 `_last_mode_error` 并在面板显示"模式切换失败：…"——失败必须用户可见。

**验证**（`tests/probe/probe_hidden_flow.gd`，真实驱动）：
HIDDEN → `err=0`、`minimized=true`、`window_mode=1`；恢复 FLOATING → `minimized=false`、`window_mode=0`。

**回归断言**（`test_app_smoke.gd`，5 条）：平台拒绝时返回错误、失败后模式回滚、
不记录为已隐藏、失败原因进入诊断、诊断暴露平台窗口状态。
headless 下 `_can_hide_natively()=false`，正好覆盖"平台拒绝"分支；GUI 运行覆盖成功分支。

**边界（不夸大）**：最小化窗口不在桌面渲染，但**任务栏条目是否消失取决于窗口样式**，
托盘级"完全不可见"尚未实现（P1 可用 WINDOW_HANDLE + Win32 ShowWindow 或 GDExtension）。
本轮验证在编辑器运行环境完成，WIN-06 仍须导出构建复验。

## 3.4 FULL 面板裁切的真正根因（复验 §5）

上轮我以为 ScrollContainer 已解决裁切，复验证明没有。实测（`tests/probe/probe_layout.gd`）：

- `FullPanel.size = 384×256`，而 `MarginContainer = 440×256` —— 子容器比面板还宽；
- `ScrollContainer` 高度塌成 **0**，诊断区实际不可见。

根因是 **`window/stretch/mode="canvas_items"` + 基线 256×256**：窗口 960×640 时缩放 =
min(960/256, 640/256) = 2.5，UI 画布只有 **384×256**（384 = 960/2.5，与实测完全吻合）。
按钮被压成两行后总高 305 超出可用 232，右侧"退出"被裁；宠物在 FULL 下也会被放大 2.5 倍。

修复：`stretch/mode="disabled"`（窗口像素 = 画布单位，FLOATING 256/256 缩放 1.0 不变）；
按钮行 `HBoxContainer` → `HFlowContainer`（窄窗口自动换行）；诊断区最小高度 120。
实测（重排后测量，切模式同帧测量会拿到重排前的最小尺寸）：面板 960×640、
六按钮一行（"退出"右边界 408 < 960）、诊断区 533 高。
截图核对：`user://shots/full_panel.png`、`floating.png`（`probe_screenshot.gd`）。

回归断言（4 条）：面板覆盖窗口、按钮无越界、诊断区高度充足。
**已验证该断言能抓住旧 bug**：临时改回 canvas_items 后断言失败
（`面板 384×256 覆盖窗口 (960,640)`），随后还原。

## 3.5 同期修掉的测试卫生缺陷

`clear_all_for_test()` 重置了 `_save_id/_revision/_autosave_stopped/_last_error`，
**唯独没重置写入锁**——"先触发锁、再清档"的用例会一直锁定，后续写入被误判失败。
本会话实测到一次该形态的偶发失败（`SAVE-01 created_at 不因加载改变`，批量复跑 6 次未再现），
修复后批量 3 连跑全绿。同时给该断言补了期望/实际值输出，便于未来诊断。


## 4. 实施期实测到的引擎事实（影响文档判断）

1. **`Window.mouse_passthrough` 在 4.7.2 是 bool**（整窗穿透）；局部多边形另在 `mouse_passthrough_polygon`。
   → 官方描述仍不保证跨应用命中，WIN-02 必须在导出构建上实测。
2. **`StatusIndicator` 没有 `is_system_tray_available()`**；`set_menu()` 接受 `NodePath`。
   → 托盘自检只能间接进行；已实现「托盘失败即建立独立常驻小窗口」的等效入口，O-04 仍需实机确认。
3. **无 `Animation.TYPE_ROTATION`**（改名 `TYPE_ROTATION_3D`，仅 Node3D）；2D 骨骼用 `TYPE_VALUE` + `":rotation"`。
   动画须加入 `AnimationLibrary`（`AnimationPlayer.add_animation()` 已移除）。
4. **`Bone2D.rest` 默认全零（det=0）**，不显式设置会在骨架求逆时报 `Condition "det == 0"`；已在 pet.tscn 逐骨骼设置 rest。
5. **叶子骨骼告警已消除（原记「属预期行为」，2026-10-18 修复）**：`Head/ArmLeft/ArmRight`
   无 Bone2D 子节点时，Skeleton2D 每次加载都会输出 `No Bone2D children of node …`
   （`skeleton_2d.cpp:451`）并退化用 transform 旋转兜底。
   实测：4.7.2 的 `Bone2D` **没有** `default_length` 属性（仅 `rest`、
   `auto_calculate_length_and_angle`、`editor_settings/show_bone_gizmo`），
   但 .tscn 中的 `default_length` 仍被读取生效（实测 `Head.length=20.0` 与设计值一致）。
   修复：为三根叶子骨骼加 `auto_calculate_length_and_angle = false`。
   验证：GUI 运行无引擎告警，`test_animation.gd` 25 条全过，全量 230 条全绿。
6. **4.7.2 没有 `--user-data-dir`**（`--help` 确认），测试隔离只能在应用层重定向 `user://`。
