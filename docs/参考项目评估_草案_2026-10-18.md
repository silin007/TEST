## 1. 参考项目实际是什么（实测，非推测）

解压后共 3 个源码文件、约 100 行代码：

| 文件 | 行数 | 作用 |
|---|---|---|
| `godot_plushie.gd` | 67 | `AnimatedSprite2D` 子类，IDLE / RUN / SNOOZE 三态机 |
| `godot_plushie_viewport_pet.gd` | 21 | `EditorPlugin`，把宠物挂进**编辑器主屏幕** |
| `godot_plushie.tscn` | 152 | `SpriteFrames`（3 组动画，37×37 图集切片）+ 一个 `IdleTimer` |

**关键定性：它是编辑器插件（`@tool` + `EditorPlugin`），不是桌面宠物应用。**
它的「桌面宠物」活在 Godot 编辑器主屏幕内部，因此**没有**窗口透明、鼠标穿透、任务栏托盘、独立进程、存档系统。

## 2. 机制逐条对照

| 机制 | 参考项目做法 | MOTE 现状 | 结论 |
|---|---|---|---|
| 状态机驱动动画 | `IDLE/RUN/SNOOZE` + `play()` | `idle/walk/happy/rest/look_around` + `AnimationPlayer` | 已有，且更完整 |
| 边界钳制 | `clamp(x, half_size, W - half_size)` | 窗口位置钳制 + 触边反向（`_update_walk`） | 已有，等价 |
| 朝向翻转 | `flip_h = difference < 0` | `set_facing()` → `_skeleton.scale.x`（架构 §6.2） | 已有 |
| 交互反馈 | 无（只有 `_input` 重置计时） | `react_happy` + 按实例只发一次奖励 | 已有，且更强 |
| 空闲检测 | `Time.get_ticks_msec() - last_input_time` | 无 | **架构未定义，P1 候选** |
| 空闲超时打盹 | 30 s 无输入 → `SNOOZE` | `rest` 由 `energy` 评分驱动 | 驱动源不同，**P1 候选** |
| 随机化决策间隔 | `wait_time = randf_range(1.0, 10.0)` | 固定评分 + 冷却 | **架构明确排除，不采纳** |
| 追随光标 | 目标点 = 鼠标 x | 沿屏幕可用区往返 | **架构明确排除，不采纳** |
| `is_instance_valid()` 守卫 | 有 | 已有等价检查 | 无收益 |
| `%NodeName` 唯一名访问 | 有 | 未使用 | 纯风格，可选 |
| `AnimatedSprite2D` + 图集 | 是 | `Skeleton2D`/`Bone2D`/`Polygon2D` | 架构 P0 要求骨骼动画，不更换 |

## 3. 与架构文档的直接冲突（重要）

参考项目最显眼的两个特性，恰好被 `docs/architecture.md` 明确排除：

> §177：「相同分数使用固定顺序 idle → look_around → walk；**暂不需要随机数**。」

→ 参考项目的 `randf_range` 随机化决策间隔**不能采纳**。

> §176：「P0 **亲近倾向和勇气保留数据，不强行赋予未经设计的功能**。」

→ 参考项目的「追随光标」属于亲近倾向类行为，**P0 不采纳**。

因此，参考项目中可直接搬进 MOTE 的代码**接近于零**。它解决的是不同层面的问题：编辑器内精灵动画 vs. 独立桌面应用的窗口、存档与 AI。

## 4. 建议处置（待确认）

### 4.1 P0 内不建议改动
架构要求的能力（边界钳制、朝向、交互反馈）MOTE 均已实现并经测试覆盖，参考项目未提供额外收益。

### 4.2 P1 候选（需先修订架构，本草案不实施）
「用户空闲 → 打盹」：参考项目以 `last_input_time` 为驱动源，MOTE 的 `rest` 目前由 `energy` 评分驱动。若要引入，需先在架构 §5 定义空闲语义与优先级（空闲打盹 vs. 低能量休息），再补验收用例。**在架构修订与确认前不实施。**

### 4.3 可选风格项
`unique_name_in_owner`（`%NodeName`）可简化场景内节点引用。属风格统一，不影响行为，可由你决定是否全项目推广。

## 5. 本次同时修复：运行输出的引擎告警

用户指出的输出报错为三组引擎告警：

```
WARNING: No Bone2D children of node Head. Cannot calculate bone length or angle reliably.
Using transform rotation for bone angle.
   at: calculate_length_and_rotation (scene/2d/skeleton_2d.cpp:451)
```
（`ArmLeft`、`ArmRight` 同）

**根因**：`Head/ArmLeft/ArmRight` 是叶子骨骼，Skeleton2D 无法从子骨骼推断长度与角度，只能退化用 transform 旋转兜底，每次加载都告警。

**实测确认（探针 `tests/probe/probe_bone2d.gd`）**：

- 4.7.2 的 `Bone2D` **没有** `default_length` 属性（只剩 `rest`、`auto_calculate_length_and_angle`、`editor_settings/show_bone_gizmo`）
- 可用方法为 `set_length()` / `get_length()` / `set_autocalculate_length_and_angle()`
- 但 `pet.tscn` 中的 `default_length` 仍被读取生效（实测 `Head.length=20.0` 与设计值一致），故保留
- 关闭自动计算后，长度与角度不变，动画驱动 `rotation` 仍正常（探针 `probe_bone_fix.gd`：ArmLeft 旋转随时间变化，非 0）

**修复**：在 `scenes/pet/pet.tscn` 为三根叶子骨骼加 `auto_calculate_length_and_angle = false`，长度由 `default_length` 显式给定，不再触发回退路径。

**验证**：修复后 GUI 运行输出仅剩应用自身日志，无任何引擎告警；`test_animation.gd` 25 条断言全通过；全量 230 条断言全绿。
